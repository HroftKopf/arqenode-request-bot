# Changelog — Arqenode Request Bot

## Правило ведения

После каждого изменения проекта добавляется новая запись **сверху**:
краткое описание, затронутые файлы, результаты тестов/покрытия и риски.
Полный технический разбор текущего изменения — в
[REMEDIATION_REPORT.md](REMEDIATION_REPORT.md), инструкция —
в [README.md](README.md).

## 2026-11-24 — CI/CD, README, скриншоты, проверка публикации

**Тип:** ci, docs, security.

**Статус:** CI и документация готовы; удалённый запуск ожидает push.

**Деплой/push:** не выполнялись; production-бот не запускался.

### Добавлено

- `.github/workflows/ci.yml` — GitHub Actions: Python 3.11, Ruff, compileall,
  `unittest`, coverage с порогом 80%, permissions `contents: read`, timeout 15
  минут, кэш pip.
- `docs/SCREENSHOTS.md` — безопасная инструкция по съёмке пяти скриншотов,
  тестовые данные, что скрывать и шаблон для README.
- `docs/screenshots/.gitkeep` — каталог для будущих реальных изображений.
- `CI_IMPLEMENTATION_REPORT.md` — отчёт по CI, README и security-проверке.

### Изменено

- `README.md` — CI badge, полная установка с `git clone`, требования,
  переменные окружения, тесты/покрытие, архитектура, демонстрация,
  безопасность и ссылки на документацию.
- `.env.example` — вместо синтаксически валидных dummy-ID теперь невалидная
  заглушка `ADMIN_IDS=PUT_YOUR_TELEGRAM_ID_HERE`, чтобы случайный запуск без
  настройки не выдал админку посторонним ID.

### Проверки

- В чистом окружении без `.env`, БД, логов и бэкапов: **147 тестов, 0
  провалов**; **97.95%** строк (1001/1022), **98.24%** ветвей (279/284),
  итог coverage.py **98.01%**.
- Локально с рабочим `.env`: 147 тестов, 97.65% строк, 97.78% coverage.py
  (ветка импортной ошибки конфигурации не исполняется).
- `ruff check .` — чисто; `compileall` — OK; AST-проверка грамматики Python
  3.11 — 27 файлов OK.
- YAML workflow разобран PyYAML; `actionlint` и удалённый GitHub Actions не
  запускались (push не выполнялся).
- Python 3.11 локально недоступен (только 3.14.10); зависимости
  `aiogram 3.34` и `coverage 7.17.5` требуют Python >=3.11 и совместимы.

### Безопасность

- Проверены все publishable-файлы (tracked + untracked, 39 шт.): реальных
  токенов, Telegram ID, ключей и приватных ключей нет; найдены только
  timestamp-числа в документации.
- `.env`, `requests.db`, `bot.log`, `main.py.backup`, `.env.backup` и
  `backups/` игнорируются и не staged; `git check-ignore` подтверждает.
- Новые файлы не содержат секретов.

## 2026-11-23 — Bugfix & remediation (14 проблем аудита)

**Тип:** security, bugfix, architecture, tests, docs.

**Статус:** 13 проблем исправлены полностью, FSM — частично (персистентность
сознательно не добавлялась).

**Деплой:** не выполнялся. Реальный Telegram API не вызывался.

### Исправлено

- **P0.** Права `.env`, `requests.db`, логов и бэкапов ограничены `600`;
  `backups/` — `700`; `.gitignore` дополнен. Удалён fail-open fallback
  `ADMIN_IDS`, настройка стала обязательной и строго валидируется.
  Добавлен rate limiting для create/reply/edit/cancel/status.
- **P1.** Уведомления: обработка 403/429/сетевых сбоев, ограниченные повторы,
  информативные логи без текстов сообщений и токена, уведомление админа о
  сбое доставки клиенту. SQLite: WAL, `BEGIN IMMEDIATE`,
  `PRAGMA user_version` v1→v2→v3, транзакционные миграции, аудит.
  История: порядок «от новых к старым», snapshot-пагинация по `max_id`,
  маркер обрезанных сообщений. `redraw` не создаёт дубликаты при
  `message is not modified`. Явные переходы статусов, корректные
  `missing`/`closed`, `on_error` не скрывает ошибки.
- **P2.** Стабильные коды статусов `new/work/wait/done/cancel` с миграцией
  существующих записей; централизованные константы; журнал `admin_actions`;
  удалены неиспользуемые импорты; относительные пути резолвятся от каталога
  проекта; зависимости зафиксированы (`requirements.txt`, `requirements.lock`,
  `requirements-dev.txt`); добавлены `pyproject.toml`, `ruff`, `coverage`.

### Проверки

- Тесты: **147**, провалов **0**, ошибок **0** (исходно было 4).
- Покрытие: **97.65%** строк (998/1022), **98.24%** ветвей (279/284),
  итог `coverage.py` — **97.78%** (исходно 19%).
- `ruff check .` — чисто; `compileall` и импорт всех модулей — OK.
- Миграция проверена на копиях реальной БД: `requests.db` 6→6 заявок,
  1→1 сообщение, `user_version=3`, `integrity_check=ok`, FK-нарушений 0;
  legacy `requests.db.backup` 3→3, без потерь. Оригиналы не изменялись.
- Секреты: в исходниках/тестах/логах токен не найден; в коде нет зашитых ID
  администраторов.

### Затронутые файлы

- Новые: `rate_limit.py`, `pyproject.toml`, `requirements-dev.txt`,
  `requirements.lock`, `CHANGELOG.md`, `REMEDIATION_REPORT.md`,
  `tests/support.py` и 12 новых тестовых модулей.
- Изменены: `config.py`, `database.py`, `helpers.py`, `keyboards.py`,
  `models.py`, `main.py`, `handlers/*.py`, `README.md`, `.env.example`,
  `.gitignore`, `requirements.txt`, `tests/test_database.py`.
- Защищённая резервная копия: `backups/20261123T203713Z/`
  (`.env`, `.env.backup`, `requests.db`, legacy-бэкап, `SHA256SUMS`).

### Риски и ограничения

- FSM и rate limiting хранятся в памяти; после рестарта окна/диалоги
  сбрасываются. Для нескольких процессов нужны общий FSM-store и rate limiter.
- Реальная БД намеренно не мигрирована; миграция произойдёт при первом запуске.
  Перед запуском бэкап уже создан.
- Токен остаётся на диске (`.env` и защищённая копия). При подозрении на
  утечку — перевыпустить через @BotFather, затем убрать старые копии.
- Старые `main.py.backup`, `requests.db.backup`, `.env.backup` и `bot.log`
  сохранены по требованию «не удалять»; права `600`.
- Git-репозитория пока нет; `.gitignore` готов. 24 непокрытые строки — в
  основном rollback-ветки БД и импортный fail-closed путь конфигурации.
