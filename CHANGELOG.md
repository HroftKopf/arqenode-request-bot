# Changelog — Arqenode Request Bot

## Правило ведения

После каждого изменения проекта добавляется новая запись **сверху**:
краткое описание, затронутые файлы, результаты тестов/покрытия и риски.
Полный технический разбор текущего изменения — в
[REMEDIATION_REPORT.md](REMEDIATION_REPORT.md), инструкция —
в [README.md](README.md).

## 2026-11-23 — Bugfix & remediation (14 проблем аудита)

**Тип:** security, bugfix, architecture, tests, docs.  
**Статус:** 13 проблем исправлены полностью, FSM — частично (персистентность
сознательно не добавлялась).  
**Деплой:** не выполнялся. Реальный Telegram API не вызывался.

### Исправлено

- **P0.** Права `.env`, `requests.db`, логов и бэкапов ограничены `600`;
  `backups/` — `700`; `.gitignore` дополнен. Удалён fail-open fallback
  `ADMIN_IDS`, настройка стала обязательной и строго валидируется.
  Добавлен rate limiting для create/reply/edit/cancel/status.
- **P1.** Уведомления: обработка 403/429/сетевых сбоев, ограниченные повторы,
  информативные логи без текстов сообщений и токена, уведомление админа о
  сбое доставки клиенту. SQLite: WAL, `BEGIN IMMEDIATE`,
  `PRAGMA user_version` v1→v2→v3, транзакционные миграции, аудит.
  История: порядок «от новых к старым», snapshot-пагинация по `max_id`,
  маркер обрезанных сообщений. `redraw` не создаёт дубликаты при
  `message is not modified`. Явные переходы статусов, корректные
  `missing`/`closed`, `on_error` не скрывает ошибки.
- **P2.** Стабильные коды статусов `new/work/wait/done/cancel` с миграцией
  существующих записей; централизованные константы; журнал `admin_actions`;
  удалены неиспользуемые импорты; относительные пути резолвятся от каталога
  проекта; зависимости зафиксированы (`requirements.txt`, `requirements.lock`,
  `requirements-dev.txt`); добавлены `pyproject.toml`, `ruff`, `coverage`.

### Риски и ограничения

- FSM и rate limiting хранятся в памяти; после рестарта окна/диалоги
  сбрасываются. Для нескольких процессов нужны общий FSM-store и rate limiter.
- Реальная БД намеренно не мигрирована; миграция произойдёт при первом запуске.
  Перед запуском бэкап уже создан.
- Токен остаётся на диске (`.env` и защищённая копия). При подозрении на
  утечку — перевыпустить через @BotFather, затем убрать старые копии.
- Старые `main.py.backup`, `requests.db.backup`, `.env.backup` и `bot.log`
  сохранены по требованию «не удалять»; права `600`.
- Git-репозитория пока нет; `.gitignore` готов. 24 непокрытые строки — в
  основном rollback-ветки БД и импортный fail-closed путь конфигурации.
